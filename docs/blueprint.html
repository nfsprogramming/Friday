SYS-01

Technology Stack — Final Decisions

Not "consider these options." These are the picks, with reasoning.

Layer Choice Why — Not Alternatives
LLM Qwen2.5-7B-Instruct Q4_K_M via Ollama CHOSEN Best tool-calling + coding at 7B. Fits in 5.5 GB VRAM. Llama3.2 is weaker at instructions. Gemma2 has no function calling. Future upgrade path: Qwen3-8B → DeepSeek → Llama.
STT faster-whisper — start tiny, upgrade to medium CHOSEN Start with whisper-tiny for MVP (lowest latency, lowest RAM). Upgrade path: base → small → medium as you tune. CTranslate2 backend is 4× faster than original Whisper regardless of model size.
TTS Piper TTS — en_US-ryan-high CHOSEN Fastest local TTS. Ryan voice is the closest to a composed assistant voice. Under 100ms latency. Kokoro is good but heavier.
Backend Python 3.11 + FastAPI CHOSEN Async WebSocket support. Best AI ecosystem. FastAPI over Flask for streaming responses. Config via YAML + .env (easy to edit, environment-separated).
Desktop UI Tauri v2 + React CHOSEN You already know Tauri. Native OS access for automation. Rust sidecar for Piper. No Electron bloat. Build UI last — terminal brain first.
Mobile Flutter (same as SpotiFLAC) CHOSEN You already have Flutter setup. Same WebSocket client as desktop. Cross-platform single codebase.
Memory DB SQLite + ChromaDB CHOSEN SQLite for structured facts/prefs/tasks/logs. ChromaDB for semantic memory search. Both embedded, zero infra. Future: PostgreSQL only if multi-device sync needed.
Embeddings Sentence Transformers — all-MiniLM-L6-v2 CHOSEN Powers ChromaDB semantic search. Fast, lightweight, runs entirely on CPU. Future models: BGE, E5, nomic-embed.
Wake Word OpenWakeWord — "hey friday" model CHOSEN Runs on CPU at <1% usage. More accurate than porcupine free tier. Custom model trainable for "Hey Friday" specifically.
Desktop Automation PyAutoGUI → pywinauto (upgrade path) CHOSEN PyAutoGUI for MVP (mouse, keyboard, window interactions). Upgrade to pywinauto + Win32 API for reliable production control. psutil for system metrics throughout.
Browser Automation Playwright CHOSEN Modern, stable, fast. Chromium + Firefox + Edge support. Selenium rejected — slower, more maintenance overhead.
Vision OpenCV + EasyOCR + moondream2 CHOSEN OpenCV for screenshot processing + image analysis. EasyOCR for text extraction from screen. moondream2 (1.8B via Ollama) for natural language screen Q&A. Split by task — don't use moondream2 for pure OCR, it's slower than EasyOCR.
Scheduler APScheduler CHOSEN Handles reminders, recurring tasks, background jobs, and workflow execution. Embedded Python — no separate process needed.
Tool System Custom JSON tool calling (Ollama format) + Permission layer CHOSEN Ollama supports OpenAI-compatible tool calling natively with Qwen2.5. Every action gets a risk level: SAFE (auto-execute) / WARNING (confirm) / DANGEROUS (explicit approval). No LangChain — direct is faster and you understand it.
Plugin System Custom Python Plugin Architecture FUTURE v2.0 Dynamic loading, hot reloading, permission isolation. Build after core is solid. Goal: plugin marketplace support.
ℹ NO LangChain. NO LlamaIndex. NO cloud APIs. These abstractions add latency and hide what's happening. Build direct — you'll understand it and it'll be faster.

✓ Total latency target: <1.5s end-to-end for a spoken command to spoken response. Achievable on your RTX 4050.
⚡ OPTIMIZATION: For known commands (open Chrome, play music, what time is it) — skip the LLM entirely. Rule-based intent → direct execution → Piper TTS. Target: <400ms for direct commands.

⚡ Streaming TTS — The JARVIS Latency Trick

Don't wait for the LLM to finish. Feed Piper sentence-by-sentence as tokens arrive. Friday starts speaking while still thinking. This cuts perceived latency by 40–60%.

async def stream_response_to_speech(prompt: str): sentence_buffer = "" tts_queue = asyncio.Queue() # TTS worker runs in parallel — consumes sentences as they arrive async def tts_worker(): while True: sentence = await tts_queue.get() if sentence is None: break await piper_speak(sentence) # non-blocking audio asyncio.create_task(tts_worker()) # Stream tokens from Ollama async for token in ollama_stream(prompt): sentence_buffer += token # Flush on sentence boundary — don't wait for full response if sentence_buffer.endswith((".", "!", "?", ",")): await tts_queue.put(sentence_buffer.strip()) sentence_buffer = "" # Flush remainder if sentence_buffer.strip(): await tts_queue.put(sentence_buffer.strip()) await tts_queue.put(None) # signal done
ℹ Flush on commas too — "Launching Chrome, Boss." feels instant vs waiting for the period. Tune the sentence_boundary tuple to your preference.
